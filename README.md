## 🔍 它会做什么？

根据对当前文件的静态分析，其执行逻辑会尝试进行以下操作。各项是否成功取决于系统版本、组件状态、权限及策略。

1. **关闭虚拟化组件**：使用 DISM 禁用 Hyper-V 相关功能、Windows 虚拟机监控程序平台、虚拟机平台和 Windows 沙盒等组件。
2. **修改启动配置**：执行以下命令，关闭 Windows 虚拟机监控程序的启动：

   ```cmd
   bcdedit.exe /set hypervisorlaunchtype off
   ```

3. **修改安全相关注册表设置**：尝试将 VBS，以及 Device Guard 下内存完整性、Credential Guard、System Guard、内核影子堆栈、Windows Hello 和安全生物识别等相关设置置为关闭。
4. **调整服务启动方式**：检查 `HvHost` 和 `vmms` 服务，在满足程序条件时将启动方式改为手动。
5. **记录日志**：程序包含日志路径 `log\hyperV_disable.log`，完成时提示重启电脑后生效。

以上结论来自文件内容和代码检查，**未通过运行该程序进行验证**。

## 🚀 使用方法

1. 确认自己的问题与 Windows 虚拟化功能有关，并阅读下方的影响说明。
2. 保存正在处理的工作，建议提前创建系统还原点或记录相关设置。
3. 下载 EXE，右键选择 **以管理员身份运行**。
4. 等待程序处理完成，按提示手动重启电脑。
5. 重启后检查原来的问题是否解决；如果无效，不建议反复运行。

## ⚠️ 运行前需要了解

- **可能影响虚拟化软件**：Hyper-V 虚拟机、WSL 2、Windows 沙盒，以及使用相关虚拟化后端的 Docker Desktop 等功能可能无法正常使用。
- **可能减少系统安全保护**：工具会尝试关闭内存完整性、Credential Guard 等保护措施，请自行权衡兼容性需求。
- **不保证解决游戏问题**：不同游戏、反作弊版本和电脑配置的要求不同，关闭这些功能未必适用。
- **不等于关闭 BIOS 虚拟化**：静态分析发现的是 Windows 层面的修改，未发现直接修改 BIOS/UEFI 中 VT-x、AMD-V 或 SVM 开关的证据。
- **恢复可能涉及多项设置**：不能只依靠一条反向命令完整恢复；如需恢复，应结合原有配置重新启用组件、安全设置和启动选项，或使用事先创建的还原点。
